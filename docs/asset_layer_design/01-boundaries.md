# 资产层边界

## 普通资产层

普通资产层管理可复用的资料资产，核心类型先收敛为：

- `item`：玩家持有、可装备、可消耗物。
- `prop`：场景线索、机关器物、不可携带或未归属物。
- `character`：主玩家、副玩家、NPC、敌人、中立角色等角色资产。

普通资产层负责保存业务语义、状态、归属关系、展示资格和关联渲染结果。它不直接决定地图绘制，也不直接承载 CG 生成任务。

固定分类和自定义分类可以进入同一个资产分类系统。固定分类负责基础资产语义，自定义分类由团的类型和本地资料流生成，作为本团专属资料维度。自定义分类不是地点、章节、角色、物品、地图的同义词，也不承担替代固定分类的职责。

普通资产层的核心价值有两层：资产本体进入本地资产层后，就应当能在前端资产层看到；资产状态详情则需要按本轮更新或玩家请求决定是否展示。LLM 不直接读取完整本地资产文件，只读取由本地代码整理后的摘要。

## 前端展示边界

本地资产存在，等于前端资产层可见。需要控制的是“状态详情/状态更新”的展示，而不是资产本体是否出现：

- 初始化时可以告诉前端有哪些初始化资产，这些资产进入资产层后应当可见。
- 如果故事没有更新某个物品状态，且玩家也没有请求查看或更新物品状态，前端不显示该物品的状态更新详情。
- 如果本轮没有请求 `inventory`、`asset_status` 或对应模块，前端不主动展开状态详情。
- 本地资产层仍要保留资产本体。需要给 LLM 时，由本地代码生成摘要输入，不把完整资产文件直接塞给模型。

## 角色资产边界

角色资产需要分层，但结构应同源。主玩家、副玩家和 NPC 使用同一套角色资产骨架，只是规格不同，并且不要放在同一个文件中：

- 主玩家：最高规格，引用现有 `player_state.json.character_card`、角色属性、状态、视觉契约和长期记忆。
- 副玩家/伙伴：次高规格，引用现有 `companion_profiles.json`、`companion_card`、关系、能力、视觉契约和长期状态。
- NPC：基础规格，引用 `npc_profiles.json`、`npc_memory.json`、视觉契约、身份、阵营、关系和当前可见状态。
- 隐藏角色、BOSS、关键特殊角色：NPC 的升级规格，应接近副玩家或主玩家，但仍标记为非玩家角色。

建议文件分层：

- `player_asset.json`：主玩家资产。
- `companion_assets.json`：副玩家/伙伴资产。
- `npc_assets.json`：NPC、敌人、中立角色、特殊角色资产。

副玩家和 NPC 最特殊的区别是“个性”建模：

- 主玩家不需要系统固化个性。主玩家由玩家控制，资产层只保存身份、状态、属性、经历和视觉信息，避免替玩家写死性格。
- 副玩家需要稳定个性。它会长期陪伴玩家，必须保存个性、说话方式、关系倾向、成长变化和边界。
- 普通 NPC 不默认需要完整个性，只保存身份、动机、关系、当前状态和必要语气。
- 特殊 NPC、隐藏角色、BOSS、长期对手等需要较高规格个性建模，可以接近副玩家规格。

主玩家和副玩家可以作为本地资产存储，但不进入右侧普通资产夹。它们主要服务角色卡、伙伴卡、头像渲染和本地摘要。NPC 是否进入资产夹由角色公开程度和剧情确认程度决定。

现有主玩家和副玩家结构不需要重造，应作为资产层的源结构复用。资产层保存索引、关系和派生视图，具体角色卡字段沿用当前代码已有结构。

角色资产不保存运行态状态字段。副玩家和 NPC 的角色资产不需要 `stats`、`status`、`relationships` 这类字段；这些内容如果存在，应保留在各自现有状态或记忆文件中，资产层只建立身份、个性、视觉和摘要索引。

## 线索本地数据

`clue` 不进入资产层，但需要独立本地 JSON 保存。线索是本地数据，不是资产。

- 线索可以长期保留。
- 线索不进入右侧资产夹。
- 线索只有在剧情确认、玩家验证或系统判定升级后，才会转化为 `item` 或 `prop` 等正式资产。
- 不是所有线索都会升级成资产。

## 故事大纲资产

故事大纲也属于本地资产层的长期结构资产，但不属于右侧普通资产夹。现有结构已经存在：

- `story_blueprint.json`：章节、节点、目标、beat checklist、后续节点。
- `story_progress.json`：当前章节、当前节点、节点内进度、beat 状态、进度百分比。

资产层应引用这套结构，作为故事资产或结构资产保存，而不是重写一套新字段。它用于给模型提供当前故事位置、合法推进范围和长期规划。

## 地图层

地图层独立管理：

- 当前地图。
- 历史地图。
- 地图结构协议。
- 节点、路线、地点、危险、状态覆盖层。
- 地图渲染缓存。

右侧资产夹可以出现地图入口，但它只是指向当前或历史地图，不是地图本体。

## CG 层

CG 层独立管理：

- 剧情触发点。
- 生图请求。
- 图像任务状态。
- 生成结果。
- 是否进入 CG 浏览视图。

CG 是图像生成产物，不参与普通资产的 item/prop/character 分类。

## 线索层

线索层保存未确认信息：

- 玩家观察到但未确认的异常。
- 疑似物品、疑似机关、疑似敌人。
- 需要后续验证的地点或事件。

线索不进入资产夹。确认后由本地状态更新逻辑提升为 `item` 或 `prop` 等正式资产。

## 渲染产物层

渲染产物层只保存文件与生成缓存：

- PNG 路径。
- renderer 版本。
- canvas spec hash。
- image job id。
- 生成时间。

它不承担剧情语义，不决定资产是否应该展示。
