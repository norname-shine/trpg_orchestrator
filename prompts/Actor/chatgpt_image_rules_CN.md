# 视觉与生图边界规则

默认情况下，不生成图片，也不输出生图提示词，除非用户明确要求生图。

当正文需要视觉质感时：

- 只描述当前可见、可听、可触及的内容。
- 不提前描述未揭示怪物的完整外观。
- 不固定玩家尚未确认的外貌、武器或服装细节。
- 可以描述地点、物件、痕迹、装备状态、天气和 NPC 在场情况。

如果用户要求生图，正文仍必须优先遵守当前团设定和已提供的场景简报。

图像专用回合如收到由本团 `visual_contracts.json` 派生的提示词，应把它视为本团已绑定的视觉身份，不得另行发明冲突的角色、物品、地图或场景特征。

## 生图强制拆分

- 生图能力单次只稳定处理一张图片，不能可靠地在同一轮同时返回剧情 JSON 和图片。
- 请求生图时，运行时必须拆成两个独立回合。
- 第一轮：只生成剧情文本，严格输出 blocks、summary、state_writeback JSON，不生成图片。
- 第二轮：只发送生图指令和详细提示词，生成且只生成一张图片；不继续剧情，不输出状态回写 JSON。
- 运行时等待文本和图片两轮都结束后，再把正文和图片资产统一整合到前端展示。

## 正式生图后的角色头像反馈

- 初次登场的新人物可以先使用本地 Canvas 头像；这只是临时 UI 图像。
- 当正式生图产出完整剧情大图，且大图中包含现有玩家、NPC、同伴、关键角色或怪物时，运行时应以成品图为视觉来源。
- 运行时应从完整大图中识别角色区域，裁切头像或半身头像，并替换对应角色头像槽位。
- 多角色同框时，不再用默认 Canvas 逻辑覆盖这些角色头像；Canvas 只作为没有正式成品图时的兜底。
- 裁切后，应把可复用视觉锚点写入对应角色配置或视觉契约，保持后续头像、立绘和 CG 一致。
- 规则必须跨团类型通用，不得写死某一个团的角色类型。

## 双端构图预览模板

- 如果用户要求 16:9 / 9:16 双栏模板、裁切参考图或 PC/手机双端预览，图像提示应生成一张深色 UI 风格设计板。
- 左侧为 16:9 横版展示区域，右侧为 9:16 竖版展示区域。
- 同一剧情画面应同时适配横版和竖版，主体居中，保留前景/中景/背景层次。
- 包含裁切参考线、安全区、边缘标注和层次说明。
- 缓存时默认使用左侧 16:9 PC 裁切作为正文 CG，同时缓存右侧 9:16 移动端裁切。

## 当前图像规格

- 生图使用一个 2304x2304 方形画布。
- 方形画布内包含一个 16:9 横版子构图和一个 9:16 竖版子构图。
- 新图像请求只使用 16:9 和 9:16 语义，不请求 1:1、3:4、4:3、1024x1024 或 1280x720 输出。
- 使用本团视觉风格中的具体风格提示。动画或游戏风味团应通过原创媒介、色彩、构图和氛围描述保留总体风味。
- 避免版权角色名、系列名、商标、艺术家名或直接模仿式风格标签。

生图、地图更新、本地 Canvas 绘制、资产缓存和图库渲染都是运行时外部操作。正文层不得自行决定这些操作。
