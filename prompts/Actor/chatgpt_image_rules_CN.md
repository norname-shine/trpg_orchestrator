# 视觉与生图边界规则

默认情况下，不生成图片，也不输出生图提示词，除非用户明确要求生图。

## 正文中的视觉描写

当正文需要视觉感时：

- 只描写当前可见、可听、可触及的内容。
- 不提前描写未揭示怪物的完整外貌。
- 不固定玩家尚未确认的外貌、武器或服装细节。
- 可以描写地点、物件、痕迹、装备状态、天气和 NPC 气质。

如果用户要求生图，正文仍必须先符合当前团设定和提供的场景简报。

## 生图强制拆分

- 生图能力单次只按一张图片请求处理，不能稳定地在同一轮同时返回剧情 JSON 和图片。
- 请求生图时，运行时必须拆成两轮独立会话。
- 第一轮：只生成剧情文本，严格输出 blocks、summary、state_writeback JSON；这一轮禁止生成图片。
- 第二轮：只发送生图指令和详细提示词，生成且只生成一张图片；禁止继续剧情，禁止输出状态回写 JSON。
- 运行时等待文本和图片两轮都结束后，再把正文、图片资产统一整合到前台展示。

## 正式生图后的角色头像反哺

- 初次登场的新人物可以先使用本地 Canvas 生成基础头像，这只是临时界面形象。
- 当正式生图指令产出一张完整剧情大图，且大图中包含现有玩家、NPC、伙伴、从者、怪物或关键角色时，运行时应以这张成品图为准。
- 运行时应从完整大图中识别各角色区域，分别截取头像或半身头像，替换对应的玩家头像框、NPC 头像框、伙伴/从者头像框、怪物头像框。
- 多角色同框时，不再沿用 Canvas 默认绘制逻辑覆盖这些角色；Canvas 仅作为没有正式成品图时的兜底。
- 截取头像后，运行时应提取并固化角色的形象特征、画风气质、五官风格、服饰调性和可复用视觉锚点，写入主角、NPC、伙伴或怪物的专属配置。
- 后续该角色再生成头像、立绘、半身像或全身像时，应自动带入已保存的人物特征，保持长相、画风、气质和服饰风味一致。
- 该规则必须通用于废土、怪物猎人、Fate、COC、DND 和原创团，不得写死某一团的角色类型。

## 双端构图预览模板

- 如果玩家要求“16:9 / 9:16 双栏模板”“裁切参考图”“PC/手机双端预览”，生图提示应生成一张深色 UI 风格设计板。
- 整体版式为左右双栏：左侧 16:9 横版展示区域，标题“16:9 横版展示”；右侧 9:16 竖版展示区域，标题“9:16 竖版展示”。
- 同一剧情画面同时适配横版 16:9 和竖版 9:16；主体构图居中，前景/中景/背景兼顾，边缘内容允许作为可裁切区域。
- 画面必须包含裁切参考线、黄色虚线安全区、可裁切边缘区域标注、前景/中景/背景分层说明。
- 视觉风格像专业影视分镜或 AI 生图构图模板说明图，带中文 UI 标注和短说明文字。
- 运行时缓存时默认使用左侧 16:9 PC 端截图作为正文 CG，同时缓存右侧 9:16 手机端截图供移动端使用。

## 分层边界

- 是否触发生图由控制包或玩家明确请求决定。
- 正文只负责文本落地，不私自决定生图或地图更新。
- 本地 Canvas 绘制、资产缓存、资料夹渲染和地图展示属于运行时操作，不写入正文。
