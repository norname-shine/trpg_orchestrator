# 资料夹资产规则

资料夹用于展示本地已知或当前可见的实体与线索。它不是长期事实的唯一来源，也不能因为显示了某张卡片就自动确认设定。

## 可展示类型

- `npc`：当前已知 NPC。
- `cg`：正式剧情 CG、生图成品、玩家可查看的大图资产。
- `servant` / `master`：Fate 类型跑团中的从者和御主。
- `monster` / `ecology`：怪物、生态线索、痕迹或压力。
- `scene` / `map`：地点、场景、路线和区域地图。
- `item`：物品、装备、补给、仪式物、线索物。
- `document` / `clue` / `anomaly`：COC 或调查型团中的文献、线索、异常。

## 固定分类 ID 规则

- 资料夹分类不允许在中途随机新增。创建跑团故事时必须一次性确定本团的分类筛选项。
- 每个分类必须绑定固定唯一 ID；前台 JSON 渲染、后台输出内容、缓存资产回收都按这套 ID 对齐。
- 只允许匹配固定 ID 白名单的内容生成资料夹卡片；不在白名单里的视觉资产、临时记录、系统说明不得新建卡片。
- `cg` 是全团通用固定筛选项，所有团默认保留；正式剧情生图必须进入 CG 分类。
- Fate 团默认固定 ID 为：`cg`（CG）、`master`（御主）、`servant`（从者）、`npc`（NPC）、`scene` / `map`（场景/地图，前台统一显示为场景）、`item`（物品）。
- 怪猎、废土、COC、DND 等团只更换开局分类 ID 配置；底层仍遵守“固定 ID、只准入、不乱增”的同一规则。
- `all` 只是前台聚合筛选按钮，不是资产分类 ID，后台不得把任何卡片的 kind 写成 `all`。

## 引用到输入框

- NPC 引用格式：`@NPC名称：`
- 物品引用格式：`查看物品「物品名称」：`
- 场景、怪物、生态和地图默认只用于查看，不自动插入行动输入。
- 引用只准备玩家输入，不替玩家决定行动。

## 展示规则

- 卡片展示标题、短详情和类型标签。
- 不展示原始 JSON。
- 详情应简洁，优先使用已确认记忆事实。
- 同一个物理物品必须只显示为一张卡片，即使状态变化也只更新详情，不创建新卡。
- 先识别稳定物品本体，再处理状态。例如“井匣升温”和“发光的井匣”仍是“井匣”；“手机彻底无信号”仍是“手机”。
- 角色、物品、场景状态更新时，必须复用原有卡片并原地更新状态、详情、缩略图或图文，不新建同类型冗余卡。
- 普通视觉资产不得私自拆成新的资料夹卡片；只有落到固定分类 ID 且能对应稳定实体的资产才可进入资料夹。
- 正式 CG 与普通 scene/map 分离：CG 进入 `cg`，地图和地点进入 `scene`，不得混用。
- 空状态应说明当前筛选没有可见资产。
- 筛选不能触发资产重建。

## 缓存规则

- 资料夹缩略图是本地 Canvas PNG 资产，通过 `/api/asset` 缓存。
- 缓存资产可以通过 `/api/assets` 列出。
- 缓存记录应尽量保留标题、详情、类型标签、来源和 generator version。
- 删除或重建资产只影响 PNG 和 asset manifest，不得修改 campaign memory。

## 多团筛选

- 筛选按钮不能写死一套。
- 怪物团可默认包含：怪物、NPC、场景、物品。
- Fate 团可默认包含：CG、从者、御主、NPC、场景、物品。
- COC 可默认包含：线索、NPC、地点、文献、异常。
- DnD 可默认包含：角色、怪物、地点、装备、任务。
- 以上只是开局配置模板；每个团在创建时确定自己的固定 ID 列表，运行中不得无规则扩展。
