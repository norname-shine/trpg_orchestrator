# 资料夹资产规则

资料夹用于展示本地已知或当前可见的实体与线索。它不是长期事实的唯一来源，也不能因为显示了某张卡片就自动确认设定。

## 可展示类型

- 固定资料夹分类只允许 `prop`（道具）、`item`（物品）、`character`（角色）、`scene`（场景）、`cg`（CG）。
- NPC、怪物、BOSS、敌对首领、御主、从者、关键角色统一进入 `character`。
- 地图和地点统一进入 `scene`。
- 线索/文献类物件进入 `item` 或 `prop`，不得新增 `clue` / `document` 固定筛选。
- 主玩家、副玩家、伙伴头像属于独立角色卡/头像槽，不进入资料夹筛选。
- 怪物生态、阶段、弱点、素材、狩猎痕迹等长期内容进入故事特有内容库；需要展示时挂到 `character` 卡详情或导演自定义资料夹。

## 固定分类 ID 规则

- 资料夹分类不允许在中途随机新增。创建跑团故事时必须一次性确定本团的分类筛选项。
- 每个分类必须绑定固定唯一 ID；前台 JSON 渲染、后台输出内容、缓存资产回收都按这套 ID 对齐。
- 只允许匹配固定 ID 白名单的内容生成资料夹卡片；不在白名单里的视觉资产、临时记录、系统说明不得新建卡片。
- 基础固定分类恒为 `prop`、`item`、`character`、`map`、`cg`。
- 导演初始化可在 `campaign_categories` 里追加 0-3 个本团自定义资料夹；4 个及以上本地拒绝。
- 怪猎、废土、COC、DND 等团的特色资源应通过自定义资料夹或角色/物品详情承载，不新增固定分类 ID。
- `all` 只是前台聚合筛选按钮，不是资产分类 ID，后台不得把任何卡片的 kind 写成 `all`。

## 引用到输入框

- NPC 引用格式：`@NPC名称：`
- 物品引用格式：`查看物品「物品名称」：`
- 场景、怪物、生态和地图默认只用于查看，不自动插入行动输入。
- 引用只准备玩家输入，不替玩家决定行动。

## 展示规则

- 卡片展示标题、短详情和类型标签。
- 不展示原始 JSON。
- 详情应简洁，优先使用已确认记忆事实。
- 同一个物理物品必须只显示为一张卡片，即使状态变化也只更新详情，不创建新卡。
- 先识别稳定物品本体，再处理状态。例如“井匣升温”和“发光的井匣”仍是“井匣”；“手机彻底无信号”仍是“手机”。
- 角色、物品、场景状态更新时，必须复用原有卡片并原地更新状态、详情、缩略图或图文，不新建同类型冗余卡。
- 普通视觉资产不得私自拆成新的资料夹卡片；只有落到固定分类 ID 且能对应稳定实体的资产才可进入资料夹。
- 正式 CG 与普通 scene/map 分离：CG 进入 `cg`，地图和地点进入 `map`，不得混用。
- 空状态应说明当前筛选没有可见资产。
- 筛选不能触发资产重建。

## 缓存规则

- 资料夹缩略图是本地 Canvas PNG 资产，通过 `/api/asset` 缓存。
- 缓存资产可以通过 `/api/assets` 列出。
- 缓存记录应尽量保留标题、详情、类型标签、来源和 generator version。
- 删除或重建资产只影响 PNG 和 asset manifest，不得修改 campaign memory。

## 多团筛选

- 筛选按钮固定基础 5 项加最多 3 个导演自定义项。
- 怪物猎人、狩猎团、生态调查团可把 `monster_ecology`、`boss_profiles`、`hunt_targets`、素材或部位破坏放入故事特有内容库或自定义资料夹，但怪物资产本体仍进入 `character`。
- COC 调查团可把线索链、文献、异常记录保存到故事特有内容库；可展示的物件进入 `item` 或 `prop`。
- 运行中不得无规则扩展固定分类；需要扩展展示维度时，只使用初始化下发的 `campaign_categories`。
