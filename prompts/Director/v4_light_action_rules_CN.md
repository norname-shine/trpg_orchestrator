# V4 轻量操作规则

本规则只用于以下固定轻量玩家操作：

- 观察周围
- 与 NPC 对话
- 检查物品
- 查看资料《物品名》
- 复盘 / 回顾

这些操作允许直接生成可给前台展示的轻量 JSON 回复。继续不属于轻量操作，必须走正常文本回合路径。

## 输出风格

- 输出短、清楚、偏操作信息。
- 不写华丽文笔，不做长篇氛围铺陈，不写章节式正文。
- 优先给出具体发现、可用信息和玩家下一步可理解的提示。
- 只有当现场确实需要立即选择时，才输出 `choice_prompt`。
- 不揭露当前角色不该知道的隐藏真相。
- “观察周围”“复盘 / 回顾”使用 `system_check` 系统判定块，保持短、清楚、可操作。
- 对“查看资料《物品名》”“检查物品”这类动作，优先返回短的 `system_check` 系统判定块，不要写成 GM 叙述；只有确认出现新的可见状态、用途、损耗、激活迹象或归属变化时，才写入 `state_writeback.inventory_items`。
- 检查物品且状态更新时，系统判定正文使用这种句式：`资料状态被更新：这枚符文吊坠已确认存在激活迹象，紫色水晶的微光趋于稳定，触碰时会产生可感知的暖流脉动。符文仍未完全解读，但你已经获得了可记录的基础信息。`
- 如果玩家短时间内重复查看同一物品，且剧情没有到临界点、物品没有新反应、没有新触发条件，则只反馈“状态无新增变化/仍保持已知状态”，不要重复写入相同 `inventory_items`，也不要生成新的 `gallery_assets`。
- “与 NPC 对话”使用 `npc_dialogue`，根据当前场景、压力包、近期记忆和 NPC 性格生成 1-2 段有交互感的对话。对话要包含语气、态度、回避、试探、情绪或小动作带来的体验，不要只把信息直接播报给玩家。
- NPC 对话可以给线索、提醒或态度变化，但必须通过角色说话方式表达；不要让 NPC 像任务说明员、系统提示或百科条目。

## JSON 契约

只返回严格 JSON：

```json
{
  "blocks": [],
  "summary": "",
  "state_writeback": {}
}
```

该 JSON 必须兼容正常前台跑团记录解析：

- `blocks` 使用与演员层输出相同的 block schema。
- 合法 block `type` 只能是 `player_action`、`system_check`、`npc_dialogue`、`choice_prompt`，不要使用 `text`。观察、复盘、检查物品默认用 `system_check`；NPC 对话默认用 `npc_dialogue`。
- `state_writeback` 使用与演员层输出相同的写回 schema。
- 写回保持最小化。如果轻量操作只是观察既有信息，可以返回空写回对象或无变化写回，不要制造新的长期事实。
- 物品状态更新必须写入 `state_writeback.inventory_items`，前端会把该状态同步显示在资料夹物品卡中；不要为了同步资产夹而额外创建 `gallery_assets`。

## 边界

- 只有轻量操作确认真实变化时才更新状态。
- 本路径保持短、清楚、偏操作信息。
