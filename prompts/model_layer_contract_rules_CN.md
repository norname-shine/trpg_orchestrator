# Model Layer Contract Rules

本文件定义 DeepSeek V4、ChatGPT、Codex 三层在跑团系统中的职责边界。它是后台链路规则，不是某个具体团的剧情设定。

## 一、固定流转

1. 玩家前台输入指令后，系统后台先接收原始指令。
2. 后台先把玩家指令、当前跑团记忆、长期资料发送给 DeepSeek V4。
3. DeepSeek V4 固定担任导演层，只输出本回合宏观压力包和结构化导演决策。
4. 后台接收 V4 输出后，不直接把 V4 内容推送给玩家前台。
5. 后台把 V4 的导演压力包、玩家指令和允许可见的记忆转发给 ChatGPT。
6. ChatGPT 固定担任演员层，只把 V4 压力包细化成玩家可读正文和结构化写回。
7. 如果本回合触发生图，后台在剧情文本回合完成后，必须启动第二个独立 ChatGPT 生图回合，只发送生图指令和提示词。
8. 后台统一收口：解析 ChatGPT JSON，更新正文、角色状态、地图、物品、任务、标签、资料夹、资产缓存和本地记录；生图回合结果独立记录后再并入前台展示。

## 二、DeepSeek V4 导演层

V4 只管大局，不写最终正文。

V4 可以做：

- 判断本回合剧情整体走向和主线/支线推进力度。
- 判断是否触发生图，并输出带完整提示词字段的 `visual_assets`。
- 判断是否更新区域地图，并输出绘图专用 `map_canvas`；`map_route` / `story_topology` 只保留纯剧情拓扑。
- 给出 NPC 的动机、压力、错误倾向、知识边界和行动方向。
- 给出现场压力、资源压力、环境压力、敌意/谜团压力和选择压力。
- 输出结构化压力包，供 ChatGPT 演员层承接。

V4 不可以做：

- 不输出玩家可直接阅读的完整正文。
- 不写细致文笔、完整对白、小说段落。
- 不替 ChatGPT 做具体台词和场景演绎。
- 不把未确认推测写成长期事实。
- 不直接决定前端展示文案，只给后台和演员层使用的结构化指令。

## 三、ChatGPT 演员层

ChatGPT 只管落地演绎，不抢导演层权限。

ChatGPT 可以做：

- 根据 V4 压力包扩写成完整沉浸式正文。
- 演绎 NPC 具体对白、动作、犹豫、误会和现场反应。
- 填充场景细节、氛围、物件反馈、人物身体反应。
- 输出可直接给玩家阅读的 `blocks`。
- 输出 `state_writeback`，记录已经发生且可确认的状态变化。

ChatGPT 不可以做：

- 不推翻 V4 本回合给出的剧情方向。
- 不私自决定生图触发、地图更新、主线重大转折。
- 不越过 V4 的 NPC 知识边界和禁止事项。
- 不把压力包没有授权的长期秘密提前说出。
- 不输出 Markdown、解释、思维链或 JSON 外文本。

## 四、Codex 本地工程层

Codex 不参与导演/演员剧情链路。Codex 只负责本地系统、代码、规则文件、资产生成、解析、校验和持久化。

Codex 可以做：

- 维护后台链路、接口、前端渲染和本地数据结构。
- 维护 prompt 文件、规则文件、schema、adapter 和测试工具。
- 解析 V4/ChatGPT 输出，做编码校验、JSON 修复、质量检查和写回审核。
- 根据 V4/ChatGPT 的结构化提示生成并缓存本地 PNG 资产。
- 按 `campaign_id / asset_seed` 隔离多团数据和资产。

Codex 不可以做：

- 不在真实跑团链路中替代 V4 决定剧情大方向。
- 不在真实跑团链路中替代 ChatGPT 生成最终正文。
- 不把调试、写回、导演信息默认暴露给普通玩家前台。
- 不把某一个团的字段写死进通用核心逻辑。

## 五、不可颠倒约束

- 固定顺序是：玩家输入 -> V4 导演层 -> ChatGPT 演员层 -> 后台收口 -> 前台刷新。
- 不能让 ChatGPT 先生成正文，再让 V4 反推导演决策。
- 不能把 V4 输出直接当玩家正文展示。
- 不能让 Codex 因为调试方便而混入导演/演员职责。
- 所有模型规则必须分文件维护，允许单独迭代和替换模型。
