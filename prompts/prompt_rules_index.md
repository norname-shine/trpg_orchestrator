# Prompt Rules Index

This index is the human-maintained map for runtime prompt rules. The machine-readable mirror is `prompt_rules_index.json`.

## Director Layer

The director layer decides pressure, pacing, boundaries, payload requests, and state hints. It may receive broad campaign memory, but not local implementation noise.

- `v4_director_prompt.md`: strict pressure-pack contract and macro turn decisions.
- `v4_campaign_context_prompt.md`: long-term campaign context rules.
- `v4_payload_fulfillment_prompt.md`: director-only payload completion pass.
- `v4_light_action_rules.md`: lightweight director-direct action path.
- `visual_asset_protocol.md`: semantic visual and map payload contract.
- Shared when triggered: `dice_check_rules.md`, `inventory_rules.md`, `dossier_rules.md`, `lazy_context_rules.md`, `output_contract_rules.md`.

## Actor Layer

The actor layer writes player-facing story JSON only. It should receive only prose-relevant visible context.

- `chatgpt_host_prompt.md`: actor output JSON and block rules.
- `chatgpt_style_rules.md`: prose and scene performance style.
- `chatgpt_npc_voice_rules.md`: NPC dialogue performance.
- `chatgpt_image_rules.md`: image boundary rules for actor-side image passes.
- `chatgpt_map_rules.md`: player-visible map narration boundary only.
- `character_card_json_rules.md`: character-card writeback rules when needed.
- Shared when triggered: `dice_check_rules.md`, `inventory_rules.md`, `dossier_rules.md`, `lazy_context_rules.md`, `output_contract_rules.md`.

## Backend Layer

The backend layer maintains local orchestration, encoding, persistence, assets, frontend behavior, validation, and audit plumbing. These rules are not actor prose instructions.

- `codex_system_architecture_rules.md`: local engineering architecture.
- `codex_computer_use_prompt.md`: browser automation boundary.
- `encoding_rules.md`: UTF-8 and prompt language policy.
- `campaign_data_lifecycle_rules.md`: campaign-scoped data lifecycle.
- `frontend_interaction_rules.md`: frontend display and interaction rules.
- `asset_cache_lifecycle_rules.md`: cache safety rules.
- `canvas_asset_generation_rules.md`: local canvas asset generation.
- `ai_flavor_check_rules.md`: local output QA and rewrite triggers.

## Hotload Layer

Hotload is the runtime selection and injection layer. It is backend-owned and should be visible to actors only as simplified capabilities.

- `prompt_modules.json`: machine registry for prompt modules, layers, and triggers.
- `custom_rules.json` per campaign: temporary campaign rules routed to director, actor, or both.
- Capability plan: local routing context; actor prompts receive only a compact visible subset.
- Lazy context rules: load only needed prompt and memory modules for the current turn.
- Output contract rules: shared schema boundary, not prose content.
- `prompt_language_sync.json`: bilingual prompt package sync baseline generated by `sync-prompts --apply`.

## Bilingual Package Policy

- English runtime prompt files and `_CN.md` Chinese packages must be paired.
- Run `python -m trpg_orchestrator.cli sync-prompts --apply` to create missing counterparts and refresh the sync baseline.
- Run `python -m trpg_orchestrator.cli sync-prompts --check` before prompt changes are considered complete.
- The sync command does not guarantee translation quality. It guarantees that one-sided prompt changes are not silently accepted after a baseline exists.

## Actor Clean Input Policy

- Actor prompts must not include backend-only map drawing, canvas, visual prompt, cache, manifest, route scheduling, payload fulfillment, debug, warning, or empty fields.
- Actor prompts should keep only player action, visible memory, current scene pressure, NPC performance direction, forbidden boundaries, choice requirements, simplified progress, and needed writeback targets.
- Deleted fields are tracked in `actor_prompt_pruned_fields.md`.
