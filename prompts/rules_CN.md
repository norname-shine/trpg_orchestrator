# TRPG 自动主持规则（中文汇总）

本文档用于人工查阅。任务清单请查看 `tasks_CN.md`。系统执行时仍以各独立 prompt / rule 文件为准。

## 一、通用系统规则

### 总体分工

- DeepSeek V4 / V5 是导演层：
  - 负责长期记忆。
  - 负责读取本地记忆。
  - 负责生成现场压力包。
  - 负责判断 NPC 动机、剧情方向、伏线推进、禁止事项。
  - 负责审核 ChatGPT 状态回写。
  - 不负责写正文。
  - 不输出普通剧情大纲。
- ChatGPT 网页客户端是演员层：
  - 负责沉浸式正文。
  - 负责选择点。
  - 负责回合摘要。
  - 负责状态回写。
  - 不展示思维链。
  - 不私自改变长期设定。
- Codex 是本地场记和自动化执行层：
  - 负责本地代码。
  - 负责本地 JSON 记忆读写。
  - 负责调用 DeepSeek。
  - 负责生成 ChatGPT 输入。
  - 负责操控已登录的 ChatGPT 网页。
  - 负责输出解析、AI 味检查、V4 审核、备份、写入和日志。

### 禁止事项

- 不使用 OpenAI API。
- ChatGPT 正文必须通过已登录的 ChatGPT 网页客户端完成。
- 不处理登录、验证码、支付、订阅、账号设置、安全验证、隐私设置。
- 不自动删除聊天。
- 不删除项目。
- 不修改账号配置。
- 找不到目标 ChatGPT 对话时停止并提示用户。
- 无法确认回复完整时停止。
- 状态回写解析失败且无法补全时停止。

## 二、V4 导演规则

### V4 必须输出

- 压力。
- 冲突。
- 误判。
- 限制。
- 现场素材。
- 禁止事项。
- NPC 当前想要什么。
- NPC 害怕什么或承受什么压力。
- NPC 可能犯什么符合身份的错误。
- 哪些信息必须自然暴露。
- 哪些信息不能直接解释。
- 本回合玩家压力点。
- 是否需要重大选择。
- 状态回写提示。
- 可视化提示 `visual_assets`。
- 地图路线提示 `map_route`。

### V4 不得输出

- 正文小说。
- 普通剧情大纲。
- “准备、出发、发现、判断、选择”的流程骨架。
- 让主线每回合强行推进。
- 让 NPC 说出不该知道的信息。
- 把未确认推测写成长期事实。
- 破坏 campaign_profile 中的世界规则。

## 三、ChatGPT 演员层规则

### 正文规则

- 只把压力包写成沉浸式正文。
- 不照搬压力包结构。
- 不展示思维链。
- 不写成任务流程。
- NPC 不像任务说明员。
- 台词不写成金句或按钮。
- 少用解释句。
- 少用“不是 A，而是 B”。
- 不让主角只是摄像机。
- 信息通过动作、环境、物件、痕迹、争执、误判、装备反馈自然暴露。
- 允许脏、旧、无用、碍事但真实的细节存在。
- 危险不能排队出现，要互相干扰、打断、遮挡、误导。
- 重大选择必须问玩家。
- 小动作、小推进、小判断由主持自动处理。
- 选择点不能给游戏化最优解。

### 输出结构

ChatGPT 当前推荐输出为严格 JSON，包含：

- `blocks`
- `summary`
- `state_writeback`

兼容旧格式：

- `【正文】`
- `【选择点】`
- `【回合摘要】`
- `【状态回写_BEGIN】`
- `【状态回写_END】`

## 四、AI 味检查规则

Codex 必须检查：

- 流水账流程。
- NPC 功能台词。
- 台词过短、过硬、像金句。
- 旁白解释太多。
- “这说明 / 这代表 / 这意味着”。
- 频繁出现“不是 A，而是 B”。
- 选择像游戏按钮。
- 主角像摄像机。
- 危险登场太规整。
- 文风太顺、太模板。
- 细节全部服务伏笔。
- 剧情跳太快。
- NPC 性格突变。
- 新增无来源设定。
- 违反 forbidden_changes。
- 状态回写把推测写成事实。

## 五、状态回写审核规则

### V4 审核结果只能是

- `accept`
- `revise`
- `reject`

### accept

- 使用 ChatGPT 原状态回写。
- 备份旧记忆。
- 写入新记忆。

### revise

- 使用 V4 修正版回写。
- 备份旧记忆。
- 写入新记忆。

### reject

- 不写入长期记忆。
- 停止并提示用户。

### V4 可以拒绝的情况

- 违反 campaign_profile。
- 剧情跳太快。
- NPC 性格突变。
- 主线秘密提前泄露。
- 装备、伤势、资源无代价恢复。
- 敌人、怪物、世界规则被魔改。
- 新增无来源设定。
- 把未确认推测写成事实。
- 把玩家未选择的重大行动写成已发生。
- 无原因覆盖长期设定。

## 六、Canvas / PNG 资产规则

### 通用规则

- Canvas 资产由本地前端生成。
- ChatGPT 不负责生成图片提示词，除非用户明确要求生图。
- 视觉资产来自已确认记忆、当前场景、V4 压力包和可见跑团记录。
- 不发明未确认外观、怪物全貌、地图终点、装备归属或物品事实。
- 不确定的内容必须标注为线索、痕迹、未知生态或当前场景占位。

### 缓存规则

- 生成资产通过 `/api/asset` 缓存。
- 保存为 PNG data URL。
- 缓存 key 基于：
  - campaign_id
  - asset kind
  - object id
  - generator version
- 绘制规则变更时递增 `ASSET_GENERATOR_VERSION`。
- 普通刷新不重复覆盖同一张可见地图。

### 地图规则

- 左侧地图展示必须使用缓存 PNG 图片。
- hidden canvas 只作为生成源。
- 可见地图比例为 16:9。
- 不提供普通用户手动刷新 / 重建地图按钮。
- 地图优先展示可读路线图，而不是复杂写实地形。
- 地图标签适配小尺寸区域。

### NPC 头像规则

- NPC 头像本地生成并缓存。
- 以稳定名称或 id 作为 seed。
- 必须在发型、头饰、胡须 / 嘴型、衣服颜色、强调色、背景色等方面做差异。
- 未确认详细外观时，头像只是界面 token，不作为长期设定。

### 物品 / 线索图标规则

- 从记忆、当前资源、装备历史、确认写回事实生成。
- 不显示原始 JSON。
- 长资源文本要拆分成多个条目。
- 未确认物品显示为线索或损耗，不显示为已确认库存。

## 七、资料夹规则

- 资料夹卡片显示：
  - 标题
  - 简短细节
  - 类型标签
- 不显示原始 JSON。
- NPC 和物品可以引用到行动输入。
- 场景、地图、怪物、生态默认只查看。
- 筛选不应触发重建资产。
- 资料夹不向普通用户提供删除缓存或重建缓存入口。

## 八、visual_assets / map_route 协议

### visual_assets 示例

```json
{
  "kind": "npc | item | scene | map | monster | ecology",
  "id": "",
  "title": "",
  "detail": "",
  "source_memory": "",
  "certainty": "confirmed | clue | uncertain | placeholder",
  "display_zone": "gallery | map | portrait | log",
  "cache_policy": "stable | scene_only | rebuild_on_version"
}
```

### map_route 示例

```json
{
  "title": "",
  "nodes": [
    { "id": "", "label": "", "certainty": "confirmed | clue | inferred" }
  ],
  "edges": [
    { "from": "", "to": "", "kind": "route | blocked | trace | danger" }
  ],
  "markers": [
    { "label": "", "kind": "clue | pressure | hazard | resource", "certainty": "confirmed | uncertain" }
  ]
}
```

### 协议边界

- V4 只提供视觉提示，不画图。
- 本地前端负责 Canvas 绘制。
- 视觉提示不自动成为长期记忆。
- 不确定内容必须使用 `clue` 或 `uncertain`。
- 如果视觉提示与 `forbidden_changes.json` 冲突，以禁止事项为准。

## 九、编码规则

- 读取文本优先使用 `read_text_auto`。
- 先尝试 UTF-8。
- 如果检测到乱码标记，再尝试 GBK。
- JSON 读取使用统一 helper。
- 新增 prompt、JSON、CSS、HTML、JavaScript 默认使用 UTF-8。
- 不在无关任务中大规模转换旧文件编码。
- 浏览器乱码应修源码编码或字符串，不应修改 campaign memory。

## 十、Computer Use 规则

- 只操作用户允许的浏览器和本地项目目录。
- 只操作当前团对应的 ChatGPT 固定对话。
- 只做粘贴、发送、等待、复制最新回复。
- 不处理登录、验证码、支付、订阅、账号设置、安全验证、隐私设置。
- 不删除聊天。
- 不删除项目。
- 不修改账号配置。
- 找不到目标对话就停止。
- 无法确认回复完整就停止。
